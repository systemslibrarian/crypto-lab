## How the classes were decided

- **REAL** — a defect in code the site actually ships, or in a workflow that actually runs.
- **TEST-ONLY** — the alert is in a test, fixture, or benchmark. For Rust this was decided by
  brace-tracking the nearest enclosing `#[cfg(test)]`, not by path: these labs keep their unit
  tests inside `src/lib.rs`, so a path filter alone would have called 25 test alerts shipped code.
- **INTENTIONAL** — the lab deliberately demonstrates the weakness the rule names, and says so
  in its own source or page text. Each one below cites the disclosure.
- **UNSURE** — nothing is left in this class. Both alerts that reached it were read and resolved.

## One caution about the Rust classification

25 of the TEST-ONLY alerts sit at paths under `crate/src` and `src/lib.rs`, which reads as
shipped code and is not. These labs put unit tests in `#[cfg(test)]` modules inside the library
file, so the path says `src` while the code is compiled only under `cargo test`. Each of those 25
was resolved by finding the nearest enclosing `#[cfg(test)]` and confirming the alert line falls
inside it. If anyone re-runs this triage with a path-based filter, those 25 will come back as
REAL and critical, and they are neither.

## What this triage does not establish

Classification was done by reading the flagged line and its surrounding code, plus each lab's
own disclosures where an INTENTIONAL call depended on one. It is not a security review of the
fleet: an absent alert is CodeQL's silence, not evidence that nothing is there. The REAL list is
the set of alerts worth acting on, ranked, and nothing in it has been acted on.
