AEGIS Gate

What does the throughput number measure? The 256 KiB row encrypts 262,144 bytes 50 times. That is 12.5 MiB. If it takes half a second, throughput is 25 MiB/s, or 26.2144 MB/s. The original chart labels the binary rate MB/s. Compare the rates for the two implementations on your device. Browser scheduling and nonce generation take time, and the lab measures no native AEGIS implementation. NIST guide to binary prefixes

Where does the random-nonce curve cross 2−32? With 96-bit nonces, move the message-count slider from 232 to 233. The estimated collision probability goes from about 2−33 to 2−31. The crossing is close to 232.5 messages. GCM with random IVs has a separate limit of 232 invocations across all devices using the same key. NIST SP 800-38D §8.3

Which bytes belong to the message? In the encrypt/decrypt exhibit, a leading U+FEFF is part of the text you enter. The UTF-8 bytes for U+FEFF followed by the letter A are ef bb bf 41. The letter A by itself is 41. The original display can make both messages look like A after a successful decryption. Check the ciphertext length: four bytes for the first message, one for the second, with either tag length.

To inspect a decrypted UTF-8 message in JavaScript while preserving that first character, use new TextDecoder('utf-8', { ignoreBOM: true }).decode(bytes). Encoding Standard, TextDecoder

Can a well-formed bcrypt string tell you whether a password matches? The string records a version, a two-digit cost, a 22-character salt, and a 31-character checksum. Checking those fields only establishes the format. A match requires a completed comparison with the same password and hash still on screen.

Ciphertext Mirror

Does every bad ciphertext produce a fallback secret? Suppose an ML-KEM-768 receiver has a valid decapsulation key. Predict the result for a ciphertext of 1,087 bytes, then for a 1,088-byte ciphertext that fails the re-encryption comparison.

The 1,087-byte input gives a length error. The 1,088-byte input reaches the comparison. A mismatch returns a 32-byte fallback secret. A match also returns a 32-byte secret. The caller receives no match flag. The required ciphertext lengths are 768, 1,088 and 1,568 bytes for ML-KEM-512, ML-KEM-768 and ML-KEM-1024, respectively.

Can a key have the right length and still fail? Compare the ML-KEM-768 keys in NIST’s sample file. For encapsulation, the largest encoded coefficient is 3,325 in case 136 and 3,330 in case 137. Legal coefficients range from 0 to 3,328. Case 136 passes the modulus check and case 137 fails, even though both keys are 1,184 bytes long.

For decapsulation, compare cases 127 and 128. Hash the public key embedded in each 2,400-byte decapsulation key with SHA3-256 and compare that digest with the stored hash. They match in case 127 and differ in case 128. A key-check failure stops the operation before the ciphertext comparison. NIST sample cases, groups 9 and 10

Collision Vault

What do the two SHAttered PDFs show? The files have different contents and the same SHA-1 digest. Compare their SHA-256 digests in the original exhibit to tell them apart. The authors report roughly 6,500 CPU-years and 100 GPU-years of computation. Read the paper at CWI for their measurements.

The announcement came in February 2017. Chrome had already announced its SHA-1 certificate retirement schedule in November 2016.

Corrupted Oracle

What happens at p = 0.01? At the 1% significance level used here, NIST’s rule rejects the sample when the measured p-value is below 0.01. An exact value of 0.01 passes this test. For example, 0.00999 fails, 0.01000 passes, and 0.01001 passes. A rounded display of 0.010 can hide which value was measured.

Does one byte give enough data for the Longest Run test? No. The original statistics function returns a passing p-value of about 0.228 for the eight bits 11111111, but the smallest NIST configuration needs 128 bits, or sixteen 8-bit blocks. The exhibit’s Run Tests button generates one million bits per generator. At that length, predict the number of 10,000-bit blocks: there are 100. NIST SP 800-22 Rev. 1a, §2.4.2

128 bits give 16 complete 8-bit blocks for Longest Run and one 128-bit block for Block Frequency.

Try 120, 128, 6,272, 750,000 and 1,000,000 bits. At one million bits, Block Frequency uses only 999,936 bits. The last 64 bits are outside its complete blocks. Its fixed 128-bit block size is smaller than NIST recommends for a sample this long. Longest Run uses every bit in this example. Block Frequency input-size recommendations, §2.2.7

For the published 128-bit Longest Run example, 4 blocks have a longest run of at most one, 9 have two, 3 have three, and none have four or more. These counts give a p-value of 0.180609, using the exact probabilities for the four categories. NIST’s worked example, §2.4.8

A pass describes one statistical test on one sample. Even predictable output can pass. NIST SP 800-22 Rev. 1a, §2.2.5–2.2.6

Entropy Collapse

What time unit does the slider use? The 28-bit preset says “millisecond clock” and the 20-bit preset says “minute-resolution clock.” Both store boot time in whole seconds. To read the displayed time, start at midnight UTC on 1 January 2024: an offset of 1 gives 00:00:01, and 60 gives 00:01:00. The presets change the range of possible inputs while keeping the same clock unit.

How much can you learn from the length of a seed? Two bits can encode four values: 00, 01, 10 and 11. Predict how likely the most common value is under each distribution, then select it. The counts below describe eight equally likely tickets.

Most likely value: 2 of 8 tickets (25%). Min-entropy: 2 bits.

Min-entropy is −log₂ of the largest outcome probability. With counts 4, 2, 1 and 1, there are still four possible values, but the most likely has probability ½. Its distribution has 1 bit of min-entropy. The byte length alone tells you how many strings fit.

In the original exhibit, move the entropy slider to 256 bits. The browser requests 32 bytes from crypto.getRandomValues. There are about 1.16 × 1077 strings of that length. Assigning each the same probability is a model assumption. This page cannot measure the browser’s underlying entropy source or identify which operating-system call supplied it.

Factor Forge

Does each extra bit double the trial-division estimate? Open The Ladder and expand “The numbers behind this chart” under Trial Division. At 8 bits the table shows 46 divisions. At 12 bits it shows 492. Four doublings would give a factor of 16, but this curve rises by about 10.7. It uses the prime-count estimate x / ln(x) with x = 2b. You can also count primes through 256 and 4,096 to get the exact counts of 54 and 564.

What changes at 0, 2 and a large probable prime? The factoring exercise accepts integers of 2 or greater. Zero is outside the domain even though it is even. Two is prime and has no proper prime factor. Enter 618970019642690137449562111 (289 − 1). This exceeds the deterministic range of the lab’s Miller–Rabin test. Passing the chosen bases supports “probably prime.” Proving that particular number prime requires additional evidence.

What does the tree establish? Enter 97, then clear the field. A tree that still shows 97 belongs to the previous input. For a large integer tested with random bases, a passing result means “probably prime.” The deterministic range shown in the exercise supports a definitive verdict.

How many bits does the balanced preset need? Its displayed integer is 1,640,344,808,434,621. It lies between 250 and 251, so its binary representation uses 51 bits. Multiplying two 26-bit integers can give a 51-bit or a 52-bit product.

FROST Threshold

Who has the whole signing key, and when? In the original exhibit, generate keys for the default three-of-five group. Count the participant cards. The trusted dealer created the group secret and issued five shares. The browser now holds all five. RFC 9591 requires the dealer to erase its secret and shares after distribution in a trusted-dealer setup.

Select three participants, complete both signing rounds, then aggregate. Each signer uses its share. The aggregator combines signature shares using public commitments and verification data. The resulting 64-byte Ed25519 signature verifies under the group public key. That check tells you whether the signature fits this key and message. It cannot tell you whether the dealer erased a copy or whether the five shares lived on separate devices. RFC 9591, Appendix C

Harvest Timeline

When does a three-year planning shortfall leave zero sensitive years for a particular record? Start in 2026. A record must stay secret for five years, migration takes ten years, and the scenario places quantum arrival twelve years away in 2038. The planning shortfall is 5 + 10 − 12 = 3 years. The record’s secrecy requirement ends in 2031, seven years before the assumed arrival. The timing calculation alone cannot establish that the record would still be sensitive then.

Compare the completion year with the arrival year in the delay table. If they are equal, migration finishes at arrival and has zero years to spare. The original table can label that case “BEAT CRQC.” In the CSV, read the column labelled “Exposed (X+Y > Z)” as the timing comparison and consider the asset’s actual confidentiality mechanism separately.

Where does the 2054 point come from? The graph extends the 2044 scenario value by five percentage points, up to a ceiling of 99%. In the pessimistic scenario, 60% in 2044 becomes 65% in 2054. The 2024 survey asked experts about five horizons: 5, 10, 15, 20 and 30 years. The lab marks three of them on its graph. Although the report includes 30-year responses, the lab calculates its own 2054 value from the 2044 scenario. Read the 2024 report.

Harvest Vault

Can a record expire before Q-Day while its library is already late to migrate? In the worked calculator example, a library starts planning in 2026. A notice stays sensitive for five years (X), migration takes six years (Y) and the assumed quantum arrival is eight years away (Z), in 2034.

A notice issued today expires in 2031. A notice issued just before migration finishes in 2032 can stay sensitive until 2037. That gives a three-year planning shortfall even though today’s notice has zero sensitive years left in 2034. Starting migration in 2028 would finish it in 2034. To allow both migration and the last notice’s five-year shelf life by 2034, the latest start would have been 2023.

The dates are assumptions. The calculator cannot tell whether anyone recorded a session. A later upgrade cannot change the protection on a copy someone already holds. NIST IR 8547 §3 · RFC 8784 §1

LLL Break

Can two different lattices have the same cell area? Use (2, 0) and (0, 1) as your first pair of basis vectors. Every point has an even first coordinate. Now use (1, 0) and (0, 2). Every point has an even second coordinate. Both cells have area 2, yet only the second lattice contains (1, 0).

In Exhibit 1, the basis-change button can add or subtract a vector, swap the vectors, or reverse one vector. Each change can be undone using integer coefficients. This reversible integer operation explains why both bases generate the same lattice. Swapping the vectors reverses the determinant’s sign and preserves its absolute value, the cell area.

Jevil

How many polynomials fit three points? Choose budget 1, two positions per signature and the Goldilocks base field. Generate a key and sign one message with the honest signer. The meter reads 3 / 4. There are exactly 18,446,744,069,414,584,321 polynomials of degree at most three that fit those three points.

A cubic has four coefficient slots. Once you choose the coefficient of the cubic term, the three points determine the other three coefficients. The field offers one choice for each of its q elements, including zero. That zero choice gives a polynomial of degree at most two.

The exact count here is q = 264 − 232 + 1. A verdict of “Exactly 2^63” rounds down to a power of two. With the tower field selected, the same 3 / 4 meter leaves q4 choices. Signing the same message again with the same key leaves the meter and the count unchanged.

Kerberos

What does a Kerberos client need to use a service ticket? The client sends the ticket with a fresh authenticator encrypted with the associated session key. The encrypted ticket alone cannot create that authenticator. Protect the credential cache because it holds both pieces. See RFC 4120 §3.2.2.

In the original lesson, try the clock at +5 minutes, then +6 minutes. The first is accepted and the second is rejected. Five minutes is the configurable MIT Kerberos default.

What proves the service’s identity to the client? Compare ctime and cusec in the last two messages. The service echoes both fields in an encrypted AP-REP. To authenticate the service, the client must decrypt and verify that reply with its ticket session key and compare both values with its own request. Seeing a sixth message is evidence that the service replied. The client’s checks establish mutual authentication. RFC 4120 §3.2.5

Key Exchange

Does a 256-bit curve send a 32-byte public key? Compare the P-256 and X25519 bars in the size chart. In TLS 1.3, P-256 sends one format byte followed by two 32-byte coordinates: 65 bytes. A compressed P-256 point takes 33 bytes. X25519 sends one 32-byte value. The bars count encoded shares before TLS framing. TLS encodings, RFC 9846 §4.3.8.2

Now compare the two directions of X25519MLKEM768. The client sends an 1184-byte ML-KEM encapsulation key and a 32-byte X25519 share, or 1216 bytes. The server returns a 1088-byte ciphertext and a 32-byte share, or 1120 bytes. The shared secret stays local: the 32-byte ML-KEM secret comes first, followed by the 32-byte X25519 secret. TLS feeds the resulting 64 bytes into its key schedule. RFC 10024 §4

In the hybrid calculator, the classical input is a toy DH value encoded in four bytes. The lab derives a 32-byte result from ML-KEM secret ‖ four-byte DH value using labelled HKDF. A result caption that puts DH first reverses the inputs used to calculate the displayed key.

LMS + HSS Vault

Which leaf can sign next? In the original lesson, generate a fresh LMS tree and sign the same notice twice. The first signature uses leaf 0 and the second uses leaf 1. The message can stay the same. Each signature spends a different one-time key.

A height-10 tree starts with 1,024 leaves. After two reservations, its next index is 2 and 1,022 leaves remain. Suppose a signer reserves leaf 2 and loses power before it can confirm delivery. Recovering safely means keeping leaf 2 spent. The next signature can use leaf 3. A signer that keeps its private key across restarts must save the advanced index before releasing a signature. RFC 8554 §5.4.1

MAC Race

Can you authenticate an empty message? In the HMAC panel of MAC Race, enter the example key key, clear the message and compute HMAC-SHA-256. Its tag begins 5d5d1395. An empty message has zero bits to flip. You can still change one key bit: replacing key with jey gives a tag beginning 16ae82e9, with 116 of 256 bits changed.

Restore key and enter the one-byte message A. The tag now begins b1d20846. Flipping the lowest bit of that message turns it into @ and changes 121 of the 256 tag bits. If the grid shows 121 for an empty message, it is displaying the example for A. The changed-bit count measures diffusion for those inputs. Authentication depends on the MAC construction and keeping the key secret. HMAC definition, RFC 2104 §2

Masked Core

When does the fourth moment differ? In Masked Core, open Scope and find “When the average hides the difference.” Choose no noise and the fourth raw moment. For secret 0 versus secret 1, the fourth moments are 44 and 41. For the secret 0 versus secret 0 control, both are 44. To check 44 by hand, group the eight even-parity bit strings by their number of ones: one has zero, six have two, and one has four. Their average fourth power is (0 + 6 × 16 + 256) / 8 = 44. Adding the same noise distribution to both groups in the control keeps their moments equal.

Where does the AES round key go? Suppose the two shares are a and b, and the round key is k. XOR the round key into one share. Recombining gives (a ⊕ k) ⊕ b = (a ⊕ b) ⊕ k. Applying the same key to both shares cancels it, because k ⊕ k = 0.

Matsui Line

NTRU Classic

Can the centered value tell you whether a coefficient wrapped? The lab reduces each integer coefficient modulo 2048 into the interval from −1023 through 1024. Predict the result for 1025, then try −1023. Both display as −1023, one unit from the edge at −1024. Only 1025 wrapped. The distance on a centered plot cannot tell you which integer you started with or give a failure probability.

1025 wraps to −1023.

Try the two endpoints, 1024 and −1024. Both give 1024 because this lab keeps the positive value at a tie. In the decryption walkthrough, the saved encryption inputs let you compare each integer coefficient of 3rg + fm with its centered value. Matching two sides modulo 2048 checks the equation even when a coefficient wraps. Hoffstein, Pipher and Silverman, §§1.4–1.5

Why does the order of the two reductions matter? Enter 2047 above. After multiplying the private polynomial by the ciphertext modulo 2048, center each coefficient first. The residue 2047 becomes −1, which gives 2 modulo 3. Taking 2047 directly modulo 3 would give 1. Now try 2046 and predict both results. After the centered values are reduced modulo 3, multiply by the private polynomial’s inverse modulo 3 to recover the message polynomial.

What did the decryption check compare? The success message means that the recovered polynomial matches the message polynomial. The original text display drops a leading U+FEFF when it decodes those bytes. That character is invisible but occupies three UTF-8 bytes. In this example the message has 17 bytes and the recovered text shown on the original page has 14.

OPAQUE Gate

Who creates the registration record, and how many bytes does the client send? Register a classroom account in Exhibit 3. The server evaluates a blinded request. The client then builds the record and sends all three fields to the server.

  • Client public key, 33 bytes in the lab’s compressed P-256 encoding.
  • Masking key, 32 bytes.
  • Envelope, 64 bytes comprising a 32-byte nonce and a 32-byte authentication tag.

The record totals 129 bytes. The server also keeps information for evaluating future blinded requests. Its OPRF secret and the demo’s credential identifier sit outside this three-field wire count. The client creates the masking key and envelope even though the original display labels both “server only.”

Nonce Collision

When is a repeat guaranteed? In the random-nonce calculator, select 32 bits and set the slider to 18. That gives 262,144 independent draws from 4,294,967,296 possible values. The original readout rounds to 100%. Multiplying the successive chances of avoiding a repeat gives a collision probability of about 99.96646%.

At slider position 32, every draw could still take a different value. One additional draw would guarantee a repeat by the pigeonhole principle. Slider position 33 passes that boundary.

ORAM Vault

Will my text fit in one block? The custom editor stores up to 32 UTF-8 bytes. Eight 📚 characters take exactly 32 bytes. Nine take 36. A leading U+FEFF followed by A takes four bytes (ef bb bf 41), even if the readout looks identical to the one-byte message A.
